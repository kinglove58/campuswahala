# Supply-chain hardening

CI action refs are full immutable commit SHAs resolved from the upstream repositories on 9 October 2026; nearby comments preserve release labels. pnpm dependencies remain exact with a frozen lockfile. CodeQL, verified-secret scan, dependency audit, two container vulnerability scans and CycloneDX SBOM generation remain enabled. No remote run is asserted by local checks.

Dependabot continues weekly npm/GitHub Actions updates and now also watches Docker references. Treat update PRs as intentional security maintenance: verify upstream repository/release provenance, review SHA/digest changes, regenerate lockfile/client, run checks/browser/container smoke/audit/scans, then promote an immutable built image digest. Pinning is not a reason to postpone security patches. Emergency CVEs use an expedited reviewed update. Never bypass a scan because of licensing or service failure; investigate and keep the release blocked or document an equivalent independent control.

Dockerfiles accept NODE_IMAGE build arguments, defaulting to development tags. Before public staging, resolve the approved Node image manifest digest for the target architecture, supply `node:<version>@sha256:<digest>` to both build/runtime stages, scan and retain that digest in release provenance/SBOM. Build/runtime must use the same approved base. The checked-in development default is not a production digest pin. A future promotion pipeline must reject missing digest arguments. CI's PostgreSQL service is disposable and loopback-oriented; production databases/caches never use public ingress. No fabricated digest is checked in.

CodeQL upload requires repository code-scanning permissions/configuration. Public repositories have applicable GitHub availability; private/internal repositories require the appropriate GitHub Code Security entitlement. Actual visibility, entitlement and successful remote analysis for kinglove58/campuswahala were not established by this local pass. Configure repository security and branch protection/required status checks before merge; do not remove CodeQL if upload fails. Secret scanning is currently verified-secret detection, not proof that all secrets are absent. Container scans currently ignore unfixed findings for failure thresholds; review/track those separately before release.

Primary guidance: [GitHub secure use](https://docs.github.com/en/actions/reference/security/secure-use) and [CodeQL availability](https://docs.github.com/en/code-security/concepts/code-scanning/codeql/codeql-code-scanning).
