# Identity and browser sessions

`IdentityProvider` is a browser authorization-code boundary. `EntraExternalIdentityProvider` targets an External ID customer tenant; `LocalIdentityProvider` is explicitly opt-in and refuses environments other than local/test. Disabled is the default. The local provider is one labelled shared demo identity, not authentication suitable for untrusted users. It accepts no caller-selected subject, email, user ID or role. No tenant, application registration, provider credentials or social-login buttons are created.

The game BFF owns cookies and fixed upstream routes. Begin accepts only an optional self-declared age band. A ten-minute database login attempt stores HMAC state/client hashes, nonce, PKCE verifier and an exact configured callback URL. Callback checks expiry, the signed browser client and single-use consumption before exchange. Entra uses code/S256, exact configured HTTPS issuer/endpoints, signature verification against JWKS, RS256 allowlisting, issuer/audience/expiry/issued-at/nonce checks and authorized-party validation. Tokens are discarded after extracting provider+subject. Email is never an identity key; multiple external identities can belong to one user without an unsafe email-linking endpoint.

The browser receives only an opaque 256-bit CampusWahala session in HttpOnly/Secure (outside local)/SameSite Strict cookies. No OAuth tokens enter localStorage or browser JSON. `cw_client` uses SameSite Lax to survive the external callback; state plus that signed cookie protects login CSRF. Guest/session cookies remain Strict. Login rotates a presented session, seven-day absolute server expiry applies, logout revokes, deletion revokes all sessions immediately. Database stores only HMAC session capabilities. API remains private behind signed BFF context, including both guest/account capabilities in request binding.

Conversion locks the user and guest inside a transaction, checks active account and live guest capability, selects actual programme/structure/stage relations and creates one private character. It stores an owner-bound 24-hour conversion receipt, deletes the guest only after character/receipt writes succeed, and supports same-owner retries. Cross-owner retries fail. If the account already has a character, keep it unchanged, consume the presented guest and record `existing_character_kept`; no silent overwrite or account merge. Conversion failure leaves the guest intact. PostgreSQL additionally guards cross-campus/programme/version/stage/semester consistency. The browser clears its guest cookie after success. It resumes the same world; temporary cosmetic coordinates survive the redirect in sessionStorage and convey no authority.

Authenticated quotas derive from the server-verified user's UUID hashed into a rate key, alongside signed browser/network limits. No caller-supplied user/role header is trusted. These stores remain single-process local-development controls. Shared atomic rate/replay storage is a public multi-replica gate. There are no public player lookup/search endpoints, role-management routes or account-linking operations.

Provider configuration must come from the actual tenant's metadata and match the registered redirect/client type. See [Microsoft External ID features](https://learn.microsoft.com/en-us/entra/external-id/customers/concept-supported-features-customers) and [jose verification](https://github.com/panva/jose). A mocked signed-token test establishes adapter behavior; it does not establish a configured Entra tenant or successful live sign-in. Production administrator MFA remains a deployment/review gate.

The configured Entra web/BFF client uses a server-only confidential credential (ENTRA_CLIENT_SECRET) outside local; it is required before enabling that provider there. The adapter supports the same credential in local tenant testing. Mock tests use no real credential. Secret/certificate provisioning remains external deployment work.

Ordinary BFF upstream requests remain bounded to five seconds. Authorization callbacks allow twenty seconds for the separately bounded token exchange and JWKS verification. All configured Entra endpoints currently must use the issuer hostname; actual tenant discovery metadata, redirect registration and confidential-client setup require a live integration review before nonlocal use.
