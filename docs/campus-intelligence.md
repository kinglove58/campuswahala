# Campus Intelligence foundation

The worker discovers five curated public official URLs across FUTA, OAU and UNILAG, then retrieves only sources marked `permitted_public`. Other permitted official/student/community public HTML adapters can use the same provider-independent extractor interface and registry; nothing crawls private groups, credentials, CAPTCHA or paywalls. Live research is opt-in with `INTELLIGENCE_ENABLED=true`. The initial adapter intentionally extracts only an observed university name from visible public text or a literal name field in bounded public JSON metadata. It does not infer faculty, programmes, slang, dates, contacts, prices or routes. More category-specific extraction adapters can be added without changing publication authority.

Pipeline: DISCOVERED → FETCHED → EXTRACTED → NORMALIZED → CORROBORATED → POLICY_CHECKED → PUBLISHED, with retained STALE/REJECTED facts/decisions and source failure/backoff. Observations retain bounded transition histories. Source registry records domain/type/campus/institution relationship, authority and editorial independent group, discovery method, policy/robots decision/time, fetch/retry times, conditional headers, hash, status and sanitized failure codes/counts. Source discovery/authority is worker-controlled, never a public client claim.

Safe fetching validates HTTP(S), exact permitted domains/ports, credentials, every redirect and all resolved IPs. It blocks non-public IPv4, non-global IPv6, IPv4-mapped/transition IPv6, localhost, link-local, multicast, metadata `169.254.169.254` and Azure platform IP `168.63.129.16`. It pins the selected validated address into the actual socket lookup, preserves TLS hostname verification, disables pooling/address-family fallback and revalidates redirects. Requests have timeout, 256 KiB body limits, MIME restrictions, three redirects and per-domain pacing. Robots is retrieved through the same boundary, denied rules apply conservatively; missing robots (404) permits public retrieval, other fetch/parser failures fail closed. Robots checks and page fetches occur on separate minute ticks. Crawl delays beyond that cadence hold retrieval. A future dedicated worker egress subnet/firewall must independently deny internal/Azure metadata traffic before public deployment.

Raw response text exists only in the bounded fetch/extractor invocation. No raw HTML, LLM transcript or internet archive is written to database/logs. Retained evidence is a maximum 240-character excerpt, locator, confidence, generated flag, observation/source/hash and timestamps. Extractor version and strict candidate schema are recorded; category must match entity type. The server checks that both the quoted excerpt and extracted value occur in the retrieved content on phrase boundaries; missing or hidden-script evidence receives zero grounded confidence. An LLM's confidence is never publication authority. Identical observation hash+extractor version is idempotent; repeat verified retrieval refreshes observation time, including conditional 304s. Facts group by campus/entity/key, values are normalized and hashed, evidence joins versions rather than duplicating a canonical fact.

Exact unambiguous normalized names/aliases can match canonical UUIDs. Unknown/ambiguous names are held as candidates; no fuzzy auto-merge. `EntityMergeHistory` stores reversible from/to references and evidence for a future authenticated exception operation, which is disabled today. Conflicting values remain separate versions and hold publication; no latest-value overwrite. Rechecks/feedback may change a policy decision without deleting its history.

Only the worker policy path writes publication/current-version selection. The API and marketing expose published, unexpired current versions with limited evidence URLs and last-observed timestamps. Fixtures stay a separate labelled preview source. The worker runs guest cleanup, account deletion and session/attempt/receipt cleanup every minute; intelligence processes at most ten due sources per tick and at most 500 expired facts per sweep. Guest cleanup remains capped at 5,000 rows. These are bounded local foundation jobs, not a deployed queue or SLA. Multi-worker leasing, database role separation, monitored backlogs and distributed pacing must precede public scale.

Metrics include source/fetch/failure/extraction/candidate/allow/held/reject/stale/contradiction counts; feedback is persisted and countable without a public trust score. Logs contain aggregate counts and error codes, no pages, capabilities, age bands or identity subjects. Admin view names are scaffolded but data access/exception mutations stay disabled until identity/MFA/permissions/auditing are implemented.

Feedback schedules source rechecks without replacing values. Significant weighted reports can hold categories without an official-only requirement; crowd feedback cannot suppress or replace official-only academic/critical facts. Guest reports transfer to the converted account (an existing account report wins duplicates) and participate in account erasure. Unconverted guest reports expire after 24 hours.
