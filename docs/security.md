# Security baseline

Target OWASP ASVS 5.0 Level 2 principles, not a certification. Financial/admin workflows require stronger reviewed controls. Browser claims, avatar coordinates and local storage cannot mint rewards or money. All authoritative commands validate schema, ownership, eligibility, state, idempotency and transaction boundaries server-side.

Implemented slice: strict Zod request schemas (no unknown fields), bounded request body, explicit catalogue stage membership, independent personal duration, preset nickname/avatar allowlists, random 256-bit capability, keyed token hash, TTL, no public ID endpoint, HttpOnly SameSite=Strict cookie, Secure in nonlocal environment, Origin checks on mutation, security headers, exact local CORS origin, per-endpoint rate limits, request IDs and sanitized errors. No upload, payment or privileged admin action exists. Phase 1 permits bounded feedback text and worker-only controlled public-source retrieval under the separate boundaries below.

## Phase 0.5 trust and retention

Signed BFF context binds method/route/body/capability, timestamp and one-use nonce. Nonlocal `/v1/*` requires service proof, including reads/catalogue; browser Origin alone grants no trust and no browser CORS allowance is emitted. Mutation Origin remains a separate CSRF check. Health endpoints are minimal private probes. Local direct-loopback tests use transport-IP pseudonyms; forwarded headers are ignored. BFF creates its own service header and accepts client IP only inside a verified ingress assertion. [ADR 005](decisions/005-bff-trust-and-abuse.md) defines keys, quotas and rotation.

Raw IP is transient, never persisted/logged. UTC-day HMAC pseudonyms and minute-lived rate/replay state are not analytics records. Independent nonlocal keys must come from Key Vault/deployment configuration; no production secrets are supplied. Shared atomic stores, private networking and verified edge canonicalization/IPv6 policy remain staging gates. Expiry cleanup is bounded and does not replace read-time authorization. See [supply-chain policy](supply-chain.md). No production-readiness certification is implied.

Local API binds loopback; nonlocal origin ingress must be private/locked down. Request IP is never read from arbitrary X-Forwarded-For. Local counters do not support multi-replica production. Next proxy caps body, forwards only method/body/content-type/capability and returns no upstream token in JSON. Authorization callback URLs contain single-use code/state parameters, not session/access tokens. No session/access tokens enter browser storage. Guest revocation deletes the guest record; account revocation invalidates the server session. Do not log cookies, tokens, bank data or raw request payloads.

Phase 1 Entra adapter implements authorization code + PKCE and validated issuer/audience/signature/expiry/nonce/state; provider tokens are discarded, and no refresh-token store exists. Future role grants must separate player, merchant, moderator, support, admin and financial privileges. MFA and reauthentication for privileged actions. Anonymous spectators require rate limits, risk challenges and moderation; opt-in public pages only. Free text chat remains disabled.

Production gates: independent threat/security review; distributed abuse control; verified OIDC; private database/network; managed identity/Key Vault; tested restore; dependency/container scans; endpoint authorization matrix; financial compliance and age/KYC before activating real money. Any removed security control requires ADR and explicit risk review.

## Phase 1 implemented boundary

Phase 1 adds OIDC code/PKCE/state/nonce/JWKS signature/issuer/audience/expiry validation and browser-bound single-use attempts; private opaque expiring/revocable sessions; row-locked capability conversion; strict user/role/privacy/feedback inputs and immediate deletion denial. Account quotas use verified principals. Worker safe retrieval pins public DNS answers, bounds redirects/time/body/MIME, blocks metadata/private addresses and honors robots/source permissions. Published-only readers independently exclude stale/held/candidate/fixture data. Routine critical approval is automated official-source policy. See the new identity/intelligence/privacy/policy documents and actual CI triage. Local demo identity and in-process abuse stores are forbidden as production substitutes.
