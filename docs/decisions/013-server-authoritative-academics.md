# ADR 013: Private action-driven academic simulation

Status: Phase 3 implementation for review. Base master `30d045545380348335d6a3a6de321fd0e4bb3e41`; no deployment or production migration.

The bounded context is one AcademicSimulation per durable character/owner, ordered AcademicTerm aggregates and compact AcademicCommandReceipts. A term stores its immutable definitions and transaction-local mutable attendance/mastery/assignment/assessment state in a bounded JSON read model. Separate tables for each lecture/assessment would add joins without providing a second independent transaction boundary. Result snapshots and progression are finalized in the aggregate. Public Campus Intelligence facts never receive simulation state.

The existing canonical Programme, ProgrammeStructure/version, ProgrammeStage/order, AcademicSemesterTemplate and character entry mode remain authoritative for placement. Migration 007 adds an explicit optional semester-to-stage relationship and backfills exact known historical fixture slugs; unmapped templates fail closed. Initial simulation-track bindings deliberately authorize only computing-demo and engineering-demo programme slugs. Other programmes show an unavailable track rather than receiving fabricated curriculum. Structure/stage/semester IDs and all course versions are snapshotted; direct-entry/transfer begin at their configured stage without invented earlier results. SIWES/industrial-training/final-project activity tags remain visible future context, without implementing their gameplay. End of configured stages yields hold/future activity review, not a fabricated graduation credential.

Pure domain functions define six distinct courses per track, with CW-CMP/CW-ENG codes, unit weights, difficulty, effort and policies. They are CampusWahala simulation content, never official FUTA/OAU/UNILAG curriculum. A four-week action-driven semester has three weekly lecture occurrences, assignments due in week 2, tests in week 3 and examinations in week 4. Course schedules do not overlap; up to twelve offerings include carryovers. Timetable venue IDs and compressed world version/geometry are snapshotted. No real lecturers or official timetable claims.

The server owns integer minutes and academic presence. Travel validates origin/destination in the same snapshotted campus venue catalogue. Simulation walking uses a versioned 5–20 minute duration derived from compressed geometry; all same-campus snapshotted venues are allowed transitions in this policy. Phaser movement, safe-return spawn writes, client clock, waypoints and cosmetic shuttle transitions never change academic presence or time. Study/work durations are strict server options. Waiting stops near the next event and then at its start; end-day/wait process every crossed event, deterministically recording missed lectures, coursework and assessments. They may cause failure, never erase requirements or award attendance. No real wall-clock-day dependency.

Every command is a strict discriminated union with a UUID commandId; non-start commands also bind a termId. Owner comes exclusively from the account session. Lock User first (same ordering as conversion/deletion), recheck status and session in the transaction, then read/write the aggregate, canonical next position and receipt. Different concurrent attempts serialize; the losing invalid transition rolls back. One active-term partial unique index protects the invariant independently. An accepted command increments revision exactly once. Replay of the same parsed command hash returns the original compact acknowledgement plus current private state; reuse of its key with different content conflicts. This separation makes acknowledgement stable while allowing two-tab refresh to see newer state. GET uses the same ownership lock for a coherent view. API rate dimensions remain client/network/verified account.

Receipts retain command ID, type, owner, term, academic minute, revision, request digest and a ≤2 KB acknowledgement. They do not duplicate private grade histories. Bound to 2,000 accepted commands per term and 100 terms per simulation; exceeding capacity rolls back safely. No receipt eviction that could execute an old key again. A later archival policy needs its own tombstone/idempotency design. Rejected commands are not durable receipts and do not mutate state. Logs retain request IDs/path/status/latency without scores or grade histories.

Scores use basis points 0–10000, grade points 0–5000, integer weights totalling 10000 and floor score arithmetic. GPA display scaling rounds to the nearest 0.001 using integer doubled numerators; exact authoritative units/quality components remain stored. Versioned deterministic preparedness strategy uses mastery, attendance and coursework; assignment scoring uses mastery and completed effort. There is no RNG in v1. Evidence snapshots record strategy/version/inputs/score; browser seeds/rolls are rejected. GPA stores attempted units and sum(units × scaled grade points), CGPA combines underlying components across all completed attempts (including failures/retakes). It never averages displayed GPAs. Completed-term database guards reject rewrites. Carryovers retain course/version/history, then appear once in the next eligible term. Game progression policy repeats when failed units reach 50% of attempted units; otherwise continues with/without carryovers through canonical semester/stage order. Every decision stores its policy version. This is game policy, not university regulation.

Private BFF routes `/api/academic/state` and `/api/academic/commands` forward signed body/guest/account-bound context to private API endpoints. They are no-store. Browser supplies no owner, score, grade, GPA, mastery gain, enrollment, clock, progression or RNG. Account deletion immediately revokes and later cascades simulation, all terms and receipts using the existing database-only concurrent worker. No additional worker secret.

Phone Portal/Schedule/results/course details and notifications consume private state; venue panels send intents through the existing typed interaction presentation. Server-derived allowed actions are presentation hints only and are revalidated. Cosmetic clock/lighting follows server academic minutes for an active account. Guest tutorial is explicitly local ephemeral demo, does not create grades/history, and is never imported during guest conversion. Offline world/map exploration remains cosmetic. No academic response is added to SW caches; no authoritative mutation queue. Lost-response retries retain only one in-memory command and require an explicit online retry with the same key. No automatic offline replay. Physical device/performance and Phase 1 production deployment gates remain open.
