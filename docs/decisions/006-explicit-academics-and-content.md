# ADR 006: Explicit programme structures and entity provenance

Status: Accepted for Phase 0.5 contracts; Phase 1 persistence/import remains future work.

A Programme owns versioned ProgrammeStructure records, each with ordered stable ProgrammeStage IDs, compatibility display codes, admission modes, configurable activity tags and explicit semester definitions. Numeric codes are labels, never inferred years. Personal duration is an independent planning preference. The current guest JSON/SQL `level` integer remains a compatibility field selected only from the server pack stages; preserving that interface avoids breaking existing temporary profiles. Normalized Phase 1 identity/state must pin structure ID/version and stage ID, academic year/semester, attempt and enrollment state. Progression/history is not implemented here. Repeats, interruption, deferment, direct entry and transfers need explicit enrollment/history records, not arithmetic. SIWES is a configured activity/stage association, not a universal year.

Campus preview pack schemaVersion 2 rejects unknown placeholder objects and checks entity references. Each programme, structure, stage, semester, location and future content record has its own evidence/status metadata. Metadata policy checks are minimum structural gates, not authentication of source quality. Cultural publication requires at least 0.8 confidence and two independent non-generated source groups; official data requires an official/institutional source; critical data additionally needs institutional policy/manual review before a future importer can publish it. Generated fixtures have confidence zero and cannot be published as generated authority. All registered preview entities must remain fixtures. Review/source authenticity enforcement and real imports remain Phase 1 work.

The engineering fixture explicitly includes a sixth stage to preserve the previous browser case; this is fictional authored compatibility content, not a verified university programme. No real content has been imported. SQL migration removes legacy level/duration arithmetic and adds an ordered expiry index without rewriting existing rows.
