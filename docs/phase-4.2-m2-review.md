## Character system

`CharacterVisual` and `CharacterAtlasCache` replace the production primitive avatar for the player and existing fictional NPCs. The approved editable source remains in `art/characters/m1/painted-campus/`; its combined source hash remains `2314f9a7d0b5d1353074804b98552b8bbc4feea8f4dbcdfcb99a3ad503eb9fc5`. The browser source is an exact LF-normalized copy with only the two relative Appearance module references renamed. The six public PNGs are byte-for-byte copies of the six approved M1 atlases. No rejected art or unselected A source enters runtime.

`node scripts/art/publish-m2-character.mjs` reproduces those public files and browser source. `node scripts/art/verify-m2-character.mjs` independently checks the source, six SHA-256 hashes, directory contents and registry without regenerating them. Existing M1 source/all-768/pose/ORA/provenance checks remain enabled in CI. Historical M1 manifests retain their original pending-approval wording; this reviewer decision supersedes that historical status, without rewriting the approved evidence.

All seven canonical Appearance fields and all 768 combinations remain supported. Six curated looks reuse immutable precompositions on demand. Other values are composed from the same approved SVG rig into one 1024×960 atlas, with forty 128×192 cells: four facings, two idle frames and eight walking frames per facing. No 768-atlas download or appearance-dependent API is added. Existing guest session save and private durable-account save/reload paths are preserved.

The scene registry shares textures by validated Appearance key. It caps active/cached textures and queued atlas jobs at six, serializes atlas jobs, decodes at most eight small SVGs concurrently, coalesces editor changes for 150 ms and composes the final look after the phone closes, releases stale acquisitions and removes unused textures. Scene disposal cancels active image loads, revokes composition Blob URLs and destroys sprites/textures. Existing zone culling and the sixteen-NPC cap remain; distant/inactive NPCs are hidden and do not advance animation. Missing curated PNGs fall back to local composition from approved source. Appearance changes retain the previous approved sprite while loading; an initial failure tries the approved B default and exposes the existing retry UI if nothing can load.

The six shipped atlases total 2,518,362 encoded bytes, loaded only when requested. Each atlas is 3,932,160 RGBA bytes; the six-texture decoded backing estimate is 23,592,960 bytes. A GPU copy can add a similar allocation: this is not measured GPU memory. One composition job adds a 3,932,160-byte canvas and at most 786,432 bytes of small decoded images plus a small body-measurement canvas/buffer. Actual browser resource timing and active/peak texture counts are in the production metrics artifact. The source avoids background uploads or authority data in asset paths.

## Camera and walking

Pure `cameraProfile` uses actual canvas dimensions, scene, resize and reduced motion. Default outdoor zoom is 1.3 on narrow screens and 1.5 on desktop, with explicit 0.8–1.2 relative zoom bounds. Body scale targets 10% of the canvas outdoors and 12% in indoor test staging. The unit suite covers 360×640, 360×800, 390×844 and desktop, zoom bounds, resize and reduced follow motion. Runtime numerical body height excludes contact/ground shadows. Reduced motion holds pose frame zero and removes follow interpolation.

The foot anchor remains `(64,177)` in the approved 128×192 cell. Collision and interaction geometry use the existing engine rules independently of art size. Camera bounds, actual Phaser resize and player follow remain in the production scene. The CW Pocket Map stays the existing wide overview; opening it pauses cosmetic walking and closing it preserves close-game zoom.

Walking poses advance by actual displacement divided by the approved projected stride, rather than by held input alone. Collision-blocked characters idle, retain their last facing and do not walk in place. Keyboard/tap walking and the final 96 world units of an automatic route now use a direction-independent 22 world units/second; source stride controls pose cadence only. See the focused pacing review for the 96-unit/five-second contract and measured evidence. Explicit Map routes retain the existing 230-world-unit/second time-compressed traversal for the distant segment; a visible fast-route label distinguishes it from the natural approach. The actor follows the actual engine path, without teleporting, hiding its position or changing proximity. The engine accepts a bounded optional presentation speed; its default remains 230 for existing consumers. Ordinary navigation now uses actual renderer-frame intervals capped at 100ms in collision-safe steps of at most 50ms, while clock/battery retain their exact original per-tick clamp. Explicit fast Map routes retain legacy timing. This prevents slow/smoothed render frames from reducing ordinary walking pace. **Only displacement changes:** elapsed/academic time, battery, safe spawns, pathfinding, collision and server authority retain their existing rules. Existing NPC patrol positions use the same distance-driven animator. A route regression test covers lecture/food arrival across four camera sizes, the switch to a natural approach and manual interruption; the retained 45-second journey deadlines remain unchanged.
